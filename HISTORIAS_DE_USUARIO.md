# Historias de usuario - Tool / Seed

## HU-01: Preparar datos de demostración

Como desarrollador, quiero sembrar datos de prueba para validar la experiencia completa de la biblioteca sin depender de información real.

Criterios de aceptación:

- El script crea libros, categorías, socios y bibliotecarios de ejemplo.
- La estructura de datos es consistente con el modelo del sistema.
- La ejecución se puede repetir sin romper integridad funcional.

## HU-02: Validar flujos de negocio

Como equipo, quiero ejecutar los datos de ejemplo para verificar escenarios de préstamo, devolución y vencidos.

Criterios de aceptación:

- El seeder genera suficientes registros para probar búsquedas y listados.
- Se incluyen casos de préstamo activo y vencido.
- Los datos permiten demostrar la lógica de reportes y estadísticas.

## HU-03: Facilitar onboarding

Como nuevo integrante del equipo, quiero usar el seeder para levantar rápidamente una base de prueba con sentido funcional.

Criterios de aceptación:

- La ejecución del script es clara y documentada.
- El proceso no requiere intervención manual compleja.
- El conjunto de datos refleja la operación real de la biblioteca.
